# モデル選択ルール

## 基本方針

トークンコストと処理品質のバランスを取るため、作業の性質に応じてモデルを使い分ける。

## モデル対応表

| フェーズ | 使用モデル | 理由 |
|----------|-----------|------|
| 指示の受け取り・理解 | `claude-opus-4-7` | 意図の読み取りミスが手戻りを生むため最高精度を使う |
| 認識のすり合わせ・確認 | `claude-opus-4-7` | 要件定義・方針決定は判断力が最重要 |
| コーディング作業 | `claude-sonnet-4-6` | Haiku より安定した品質でコスト削減 |
| ドキュメント・仕様書の更新 | `claude-sonnet-4-6` | テンプレートに従う作業でも一定の品質を担保 |
| テストケース・QA更新 | `claude-sonnet-4-6` | フォーマット追記作業に十分な性能とコストのバランス |

## 切り替えタイミングの判断基準

### Opus 4.7 を使う場面
- ユーザーから新しいタスクや指示を受け取った直後
- 要件・仕様が曖昧で確認が必要な場面
- 複数の設計アプローチを比較・提案する場面
- エラーの根本原因を調査・分析する場面

### Sonnet 4.6 を使う場面
- 認識合わせが完了し、実装内容が明確になった後
- 既存コードへの追記・修正など定型的なコーディング作業
- Markdown ファイルの更新・追記
- テストケースや QA チェックリストへの記入

## 切り替え方法

```
/model claude-opus-4-7   # 指示受け取り・確認フェーズ
/model claude-sonnet-4-6 # 作業フェーズ
```
